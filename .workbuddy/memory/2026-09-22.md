## CarLife 车机端 1.12：USB 免弹窗授权（1.11 → 112/mod1.12）

- 基线 `_w111` → 产出 `CarLife/01_工程源码/_w112`；脚本 `CarLife/02_补丁脚本/patch_v9_USB免授权.py`
- 成品：`CarLife/05_产物/CarLife4.0车机端个人修改版1.12_USB免授权.apk`
- 起因：用户问「1.11 把权限窗降到 5 秒一次，能不能干脆不让用户点」

### 弹窗真正根因（重要，之前一直没发现）
AOSP `UsbHostManager.usbDeviceAdded()` 用 `getDeviceMatches()` → `PackageManager.queryIntentActivities()`
**只认 Activity**；matches>0 时系统直接 `grantDevicePermission` 且不弹框，matches==0 才弹框。
CarLife 把 `USB_DEVICE_ATTACHED` 只挂在 **BroadcastReceiver**（`BroadcastActionReceiver`）上
→ matches 恒空 → 必然弹框。`res/xml/device_filter.xml` 是空的 `<usb-device />`（全通配），资源一直在，只是挂错组件。

### 四层免授权
- **patchQ** 新增透明 `UsbAutoGrantActivity` 声明 intent-filter+device_filter → 系统插入时自动授权；
  device_filter 另补 AOA 态 Google VID 0x18D1(6353) 六个 PID(11520~11525)
- **patchP**（核心）`c/c.smali` 的 `hasPermission()` → `f.c()` 三级判定：
  已授权记录 / 静默缓存 q / `f.e()` 静默 open+claim+close 试探。
  原理：Android USB 权限是 App 侧君子协定，`openDevice()` 跨进程到 UsbService，
  **Android 4.x 不校验授权记录表**。失败被 try/catch 吞掉 → 安全退回弹窗路径。
- **patchR** `UsbPermissionProxyActivity` 里先静默后弹窗
- **MANAGE_USB**（Manifest 已声明，signature|privileged）+ `/system/priv-app` → 100% 免授权
  配套脚本 `CarLife/03_构建脚本/install_priv_app.sh`（--uninstall 回滚）

### 又踩的坑
1. **smali 寄存器 v0-v15 硬限制又踩一次**：想用 v17/v18 暂存 UsbManager（已把 `.locals` 扩到 19、
   且给足初值避开 Dalvik 汇合冲突），apktool 直接报
   `Invalid register: v17. Must be between v0 and v15`。
   **正解：把决策逻辑整个收进静态方法，调用点只替换两行，一个寄存器都不加。**
2. 改 smali 分支时若必须在调用点内联，需要保证 :汇合点 上各路径寄存器类型一致，
   且**所有寄存器在所有路径都有初值**（Uninit 与 Reference 合并 = CONFLICT）。

### 验证
- 真机（Android 12）：versionCode=112 / mod1.12；`dumpsys package` 可见
  `UsbAutoGrantActivity` 已注册；启动零崩溃；Dalvik 合并点检查 34 方法零冲突
- **未实测**：该机 `dumpsys usb` → `host_manager num_connects=0`，无 USB Host 设备，
  静默 openDevice 走不到；本机也无 Android 4.4 设备（MuMu 已卸载）
  → 层2 是否放行需车机插手机看 `CarLifeUsb` 日志确认
- 文档：`CarLife/04_文档/1.12_USB免授权说明.md`（含日志对照表）

## CarLife 车机端 1.13：去掉开机引导界面（1.12 → 113/mod1.13）

- 基线 `_w112` → `CarLife/01_工程源码/_w113`；脚本 `CarLife/02_补丁脚本/patch_v10_去引导页.py`
- 成品：`CarLife/05_产物/CarLife4.0车机端个人修改版1.13_去引导页.apk`

### 开机两屏的定位（下次直接查）
1. **Logo 启动页** `a.a.b.n.r`(LaunchFragment) inflate `frag_launch.xml`(0x7f0c002c)，**停留 2000ms**
2. **用户引导 ViewPager** `a.a.b.n.u`(UserGuideFragment) inflate `fragment_user_guide.xml`(0x7f0c0033)
   + `com.baidu.carlifevehicle.view.DirectionViewPager`，需手动翻完

跳转逻辑在 `a/a/b/n/r.smali` 的 `onCreateView()`：
```
prefs.getBoolean("first_install_key", true)
  true  -> b(0x7d9, 2000)  # 消息 2009 -> CarlifeActivity$a:cond_9 -> k.a(u) 引导页
  false -> b(0x7d5, 2000)  # 消息 2005 -> CarlifeActivity$a:pswitch_1 -> 主界面
并把 first_install_key 写回 false
```
改法：`if-eqz p1, :cond_2` → `goto :cond_2`（永久走主界面）；`const/16 p2, 0x7d0` → `0x64`(100ms)。
`u` 类成为死代码但**保留不删**（便于回滚）。

### 又踩的坑（3 个）
1. **Python shutil.copytree 复制 2400+ 文件会超时被 SIGTERM** → 改用
   `robocopy src dst /E /NFL /NDL /NJH /NJS /NC /NS`（2.8 秒完成），脚本加 `SKIP_COPY=1` 跳过复制
2. **apktool.yml 的 versionCode 必须是裸整数**，写成 `'113'` 会抛
   `NumberFormatException: For input string: "'113'"`
3. **自检正则要处理 CRLF + 缩进**：apktool 产出是 CRLF，`^xxx$` 行锚定匹配不到；
   versionInfo 下的 `versionCode:` 有两个空格缩进。自检前先 `replace('\r\n','\n')` 并用 `^\s*`
   另外：注释里别写原代码字面量，否则 `in` 判断会命中注释（误报）

### 直连 vs 亿连结论（回答用户"现在完全一样了吗"）
**没有，也不可能完全一样。** 三类：
- **已对齐**：createGroup 自举 / 失败分级 / 退避重试 / 断线自愈 / 清理三连 / 组播锁 / 发现风暴抑制
- **结构性对不齐（改不了）**：亿连 mDNS 网内自举不依赖蓝牙，CarLife **必须蓝牙 RFCOMM 带外**；
  亿连车机是 TCP 服务端(ServerSocket×12)，CarLife 车机是 **TCP 客户端**(0 个 ServerSocket)；
  GO 角色亿连双向兼容、CarLife 固定手机 GO。
  **根因：手机端 CarLife App 是百度二进制，我们只能改车机端，协议层改不动。**
- **还能补（按收益）**：① 心跳探活（亿连 2s/失败3次判离线）② 慢扫改无限（现在 12轮×30s≈7分钟后放弃，
  亿连是无限 120s）③ IP 就绪等待 ④ 多网卡遍历

⚠️ 澄清：1.11 加的 `addLocalService`(P2P DNS-SD) **≠ 亿连的 jmdns 全网广播**。
P2P DNS-SD 只在组内有效且需对端主动 `addServiceRequest` 查询，**CarLife 手机端不会查** → 对实际连接可能无用。

## MuMu 实测 1.13 → 发现并修复自举器分支写反（1.14 / 114）

### 经过
用户重装了 MuMu（`C:\Program Files (x86)\Nemu`，进程 NemuPlayer），按 skill 连接成功（127.0.0.1:7555 / adb -P 5039）。
- 1.13 装 MuMu(Android 4.4.4)：versionCode 113、启动零崩溃、**引导页确认消失**（截图直接进主界面）
- 但自举器日志暴露 bug：8 秒检查点打印 `P2P group detected, bootstrap idle` —— MuMu 根本无 P2P，不可能有组

### bug（patchH 重写 j$b/j$a 时引入的回归，"分支写反"老坑第三次复发）
1. **j$b 有无组判断**：`i.f` 语义是 groupFormed==true → f=1（i.smali 333/388/467 行确认），
   但 j$b 写成 `if-eqz v1, :formed`（f==false 判有组）。
   后果：车机无组时永不 createGroup；有组时反而 createGroup → BUSY（也解释了早期真机 BUSY）。
   修复 → `if-nez v1, :formed`
2. **j$a.onFailure 分级**：`if-eq p1, 0x1, :check_busy` 导致 reason=1(不支持)走 BUSY 重试、
   reason=2(BUSY)直接放弃，完全对调。修复 → 常量改 0x2 + 删 check_busy 内二次比较
   （走到 check_busy 只剩 reason=2，无条件 removeGroup 后退避）

### 1.14 验证（MuMu 实测，全过）
```
armed → discover loop cancelled → MulticastLock acquired → addLocalService failed (ignored)
→ createGroup attempt 1/6 → failed reason=1 → UNSUPPORTED give up → disarmed: lock+service+group cleaned
```
零崩溃；引导页无；直连最终"连接超时"符合预期（MuMu 无 P2P）。
**分支方向 bug 只有实机日志能抓到，静态检查全过。**

   `CONFIG_TARGET_BLUETOOTH_NAME` → SPP `00001101-...` connect → 失败 2s/5s 固定重投（无退避无上限）
   **无扫描/配对环节**（startDiscovery/createBond/BOND_STATE/ACL 全零命中）
2. P2P 发现 `WifiDirectDiscoverableTask`：`[StopPeerDiscoverOperation, DiscoverPeersOperation]` 序列
   + `AtomicBoolean executing` 防重入 + **stop 失败转 onSuccess**；失败 2000ms 固定周期
3. 组形成 → `requestIp`(0x108006) → 手机回 `CarlifeWirlessIp`
   → 空 IP 且 isConnected → postDelayed 重发（IP 就绪轮询）→ `WirlessConnector.startConnect(ip)`
4. 保活 `ConnectionEstablishHandler`：**1s 发 0x20002 心跳，30s 无收包 → terminate()**

### 六项我们没有的（可移植，按收益）
心跳探活 / P2P 操作串行队列 / IP 就绪轮询 / 设备名反向适配 / 失败分级 UI 提示 / 前置自检

### 六项我们有 5+ 没有的
createGroup 自举器（5+ 全仓 0 处）/ setDeviceName / 组播锁 / DNS-SD / **蓝牙未开自动 enable()**
（5+ 直接 return）/ terminate 清理更彻底

### 协议层完全同源（重要）
SPP UUID、端口表 7240/8240/9240/9241/9242、车机同为 TCP 客户端、连接类型 2/5/9、reason 1=不支持 2=BUSY
→ 说明**两版手机端协议兼容**，差异全在工程化加固，是互补不是替代

### 别抄 5+ 的坑
- `TimerUtils` = 裸 `java.util.Timer` + 静态 Map：单线程串行，task 抛未捕获异常会干掉整个 Timer 线程
- `isConnected()` 反射失败返回 true → 误判全部已配对设备为已连接
- 蓝牙无扫描、无退避、无上限

### 结论
建议 1.15 优先移植「心跳 + stop-before-discover 队列 + IP 就绪轮询」三项。

### 结论一：1.16 的独立图标是设计错误，1.17 改掉了

1.16 给 `LogDownloadActivity` 挂了 `MAIN/LAUNCHER` intent-filter，包没变（还是
`com.baidu.carlifevehicle`，同进程同签名），但车机桌面会**多出一个图标**，看着像另一个 App。
1.17 去掉 intent-filter + `exported="false"`，改成主界面按钮。

**机器可判定的证据**（比看截图可靠）：
```
1.16: dumpsys package -> 2 条 LAUNCHER
      .CarlifeActivity / .logxfer.LogDownloadActivity
1.17: 1 条 LAUNCHER
      .CarlifeActivity（LogDownloadActivity 已从 Resolver Table 消失）
```

### 结论二：主界面按钮是怎么挂上去的（这条以后还会用）

`res/layout/frag_main.xml`（+ `layout-hdpi` 变体）右上角三个 TextView：
帮助 `0x7f0900a3` / 设置 `0x7f0900a4` / **方控 `0x7f0900a2`**（`@string/diy_button`，值是 `<u>方控</u>`）。
点击分派在 `a/a/b/n/s.smali:875` 的 `.packed-switch 0x7f0900a2` —— **别动它**，加 case 要重排跳转表。

**采用的路径**：`a/a/b/n/s.smali:378` 本来就有
`invoke-static {p2}, Lcom/baidu/carlifevehicle/ConnModeHelper;->init(Landroid/view/View;)V`，
`ConnModeHelper` 是我们自己的类、拿到的正是 frag_main 根 View。在它 `init()` 入口插**一行**
`invoke-static {p0}, Lcom/baidu/carlifevehicle/logxfer/LogXferEntry;->bind(Landroid/view/View;)V`
即可。新类 `LogXferEntry` 负责 `findViewById(0x7f090147)` + `setOnClickListener`。

- 新 id `main_btn_logxfer = 0x7f090147`：`public.xml` 与 `ids.xml` **两处都要加**（照
  `conn_mode_bar` 那批 0x7f090140~146 的追加位置）。
- 布局用 `android:layout_toLeftOf="@id/main_btn_button"`，不用算 margin，天然紧贴方控左侧。
- apktool 工程的 Java 没有 `R.java`（javac 独立编译），**id 只能硬编码**，改一处要改三处。

MuMu 实测：`uiautomator` 读出
`下载日志 bounds=[978,28]-[1114,123]`、`方控 bounds=[1128,28]-[1223,123]` —— 相邻间距 14px，在左侧。

### 结论三：CarLife 日志**有**轮转清理，不会无限增长

代码在 `a/a/a/a/n/g.smali`（tag `CarLife_SDK`，Kotlin）。三个参数在
`a/a/a/a/a/e.smali:364-442` 设定：`g`=日志级别(默认5)、`h`=**单文件 5MB**(`0x500000`)、
`i`=**目录内最多 20 个**(`0x14`)。

轮转逻辑（`n/g.smali` 的 `f(String)`，~500-1050 行）：每写一条就查当前文件
`length() > 5MB` → 关 writer → **gzip 成 .gz 并删原文件** → 列目录（**排除文件名含 "crash" 的**）
→ 按 `lastModified()` 升序（`g$b.smali` 比较器）→ 若文件数 `>= 20` 就**删掉最旧的 20%**（20→删4）。
稳态约 16~20 个文件。

落盘：`SDK_INT > 21` 用 `getExternalFilesDir(null)/log`，**否则 `getFilesDir()/log`**
→ API19 车机是 `/data/data/com.baidu.carlifevehicle/files/log/`。
MuMu 实测 1 个文件 63KB（后来涨到 81KB）。

**两个必须知道的例外**：
1. `CONFIG_MAX_LOG_FILE_SIZE` / `CONFIG_MAX_LOG_FILE_COUNT` 在整个 dex 里**只出现在读取处**
   （`e.smali:404` / `:426`），`CarlifeActivity` 从 bdcf 转发给 SDK 的 key 只有 8 个，不含这两个。
   → **这两个上限在 `assets/bdcf` 里改不了，永远取默认 5MB / 20**；想改只能改 smali
   （`:397` 的 `0x500000`、`:419` 的 `0x14`）。
2. `a/a/a/a/l/c.smali` 会往 `/sdcard/BaiduCarlife/<yyyy-MM-dd>_Carlife.log` 追加写，**没有任何清理**；
   但它的开关静态字段 `b` 只在 `<clinit>` 里被设成 6，而写入条件是 `b <= 3`
   → **恒为关闭**。MuMu 实测 `/sdcard/BaiduCarlife` 不存在。

### 顺手修的三个 bug（两个老的，一个新代码自己犯的）

1. **分支方向写反（项目第四次）**：`ConnModeHelper.init()` 刷「当前版本」处
   `if-nez v0, :cond_5` → 找到 TextView 时反而跳走，setText 永远执行不到，
   界面一直显示布局写死的 `mod1.6`。改成 `if-eqz`。
   → 复述一次：`if-eqz` = 等于 0 就跳；`if-nez` = 不等于 0 就跳。
2. 版本号字面量少了前缀（`"当前版本: "` → `"当前版本: 4.0.M1.3-"`），否则丢掉 `4.0.M1.3` 段。
3. **惰性单例直接读字段**：`LogHttpServer.summary()` 里写 `s = sInst`，但 `sInst` 是 `get()`
   里 new 的，`get()` 首次调用在 `onStart()`，`summary()` 在 `onCreate()` —— 拿到 null，
   那一行**永远空白**，不报错不崩溃，只有看截图才发现少了一行。改成 `s = get()`。
