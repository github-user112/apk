### 定位结论（都已落到代码行）

1. **直连**：阶段1 蓝牙 SPP 带外握手没做成 → 手机拿不到 SSID/PSK 就不会 join 组。
   `a/a/a/a/m/m/d/a.smali`（`BluetoothDeviceDiscover.run()`）有**三处静默 early-return**：
   - `:goto_5`: 配了 `CONFIG_TARGET_BLUETOOTH_NAME` 但无已配对设备名字匹配 → 静默 return
   - `:cond_1a`: `getBondedDevices()` 为空 → 静默 return，**且永不重试**
   - `:cond_1a`: 已配对全 connect 失败且 `d/d.h==0` → 静默 return
   **判据可信**：`a/a/a/a/n/g.smali:455` 已把 SDK 日志器 `n/g;->c()` 桥接到 `ConnLog.log()`，
   所以"屏幕上看不到蓝牙日志" = 代码真没走到打日志处。
2. **热点切换卡死**：`ConnModeHelper.selectMode()` 在**点击回调=UI 线程**上同步跑
   `m/d;->i(I)` → `m/m/b;->j()`（逐个旧任务 `f()`：停心跳/停自举/removeGroup/
   stopPeerDiscovery）+ `V()`（建新任务：`new DatagramSocket(7999)` + `Thread.start()`），
   外加 `SharedPreferences.commit()` 的同步 fsync。
   **P2P/USB 的 `f()`/`a()` 里都没有 sleep/wait/join**，所以不是死锁，是"UI 线程干了太多同步活"。
3. **热点连不上**：全仓（1.6 与 5+ 都）**没有** `WifiManager.addNetwork` /
   `WifiConfiguration` → **车机端不会自己连手机热点**，必须用户先在车机 WLAN 设置里连手机热点。
   `m/m/e/a$a.run()` 只在 UDP 7999 收手机广播（收到时 SDK 会打 `connect  packet:<IP>`）。

## 二维码打不开的根因（已定位，待修 → 计划 1.19）

用户报「日志下载的还是不行，手机端打不开你给的二维码」。

根因在 `logxfer_src/java/.../LogHttpServer.java` 的 `localIps()`：
它遍历 `NetworkInterface.getNetworkInterfaces()` 返回**所有**非回环 IPv4——
**不区分网卡、不排序、不过滤蜂窝**（`rmnet0` 的 `10.x` 也在里面）。`baseUrls()` 把前 3 个
拼成 `http://<ip>:18080`，`LogDownloadActivity.buildAssetUrl()` 用 `,` 连接塞进
`file:///android_asset/logxfer/logxfer.html#<u1,u2,u3>`，`logxfer.html` 就渲染**最多 3 个二维码**
（每个 190×190）。用户扫到的大概率是**手机根本路由不到的那个 IP**。

叠加因素：日志下载要求手机与车机**同网**。而按 1.18 的诊断，蓝牙 SPP 不通 → 手机压根没 join
进 P2P 组 → 车机的 `192.168.49.1` 手机也路由不到。**所以"打不开"多数情况下是网络层没通，
不是二维码算法错。**

1.19 要改：
1. `localIps()` 按"手机可能可达"排序并过滤：优先 `p2p0`/`192.168.49.x` → `wlan0`/`192.168.x.x`
   → 其它；**排除 `rmnet*`/蜂窝网段**
2. 页面只给**一个主二维码**（推荐地址），其余降级为小字列表 —— 一屏 3 个码只会让人不知道扫哪个
3. 界面上把**网卡名**一起显示（`p2p0: 192.168.49.1`），并加一句"手机需先连上车机 WiFi Direct 组"
   的前置条件提示，便于现场判断是"地址错"还是"网络没通"
