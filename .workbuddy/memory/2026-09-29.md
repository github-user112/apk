# 2026-09-29 车机收音机→蓝牙音源：BootTask v1.4→v1.5

## 背景
车机（tcc893x/4.4.2）开机默认进收音机；手机蓝牙连上后需在多媒体里手动切到蓝牙源。方案：BootTask 侦察版 → 车机跑一次 → QR 下载 diagnostic.txt 回传分析 → 定最终切换机制。

## v1.4 MuMu 验证结论（收尾确认）
- 3 规则开机全链路 OK：broadcast×2 + rootcmd "id"。
- rootcmd 关键日志：`su unavailable/empty-fail, fallback plain shell: id` → `rootcmd done: uid=10062... (exit=0)`。su 探测超时回退普通 shell 不挂（run() 的 available()+exitValue() 轮询方案有效）。
- 诊断页组件名是**内部类** `com.boottask/com.boottask.BootDiagnostics$LogActivity`（不是 .LogActivity）。
- adb 启动内部类 Activity 的转义坑：Git Bash+adb 双层 shell，单引号里 `\$` 会带反斜杠、不转义 `$` 会被远程 shell 吃掉。**稳妥法：printf 写脚本 push 到 /data/local/tmp 用 `sh` 跑**（脚本内容用单引号包组件名）。
- adb.exe 不认 MSYS 的 /tmp 路径（push 报 cannot stat），临时文件放 C:/PJGG/apk/ 下。

## v1.5（versionCode 6）修正：pm dump 无 DUMP 权限
MuMu 实锤：非 root 下 `pm dump <pkg>` 全部 `Permission Denial ... android.permission.DUMP`，普通 app 拿不到 receiver/service 信息。
修正 BootDiagnostics.dumpCandidates：
- root=true → `su -c "dumpsys package <pkg>"`（整条命令作为 su -c 单参数，防空格拆分）
- root=false → 保持 pm dump（输出也行）
- 新增 filterComponentLines()：按 receiver/service/activity/filter/action/category/permission/exported/priority/denial 关键词过滤 + 每包 60 行上限，防 dumpsys 全量输出撑爆诊断文件
- envRecon 的 root 探测结果传入 dumpCandidates
MuMu 复验：version=1.5 (6)、过滤生效、无崩溃无 ANR。su 路径 MuMu 验不了（授权对话框），依赖 run() 既有超时回退兜底；真机 eng 固件大概率 su 可用。

## 构建脚本修复
build_win.sh 在当前 Git Bash 环境把 MSYS 路径（/c/...）传给 Python copytree 报找不到路径。修：`ROOT=$(... && pwd -W)`、`WORK=$(cygpath -m "$(mktemp -d ...)")`、默认产物改 v1.5。
