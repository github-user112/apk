- 新增「文件管理器」：架构为车机只跑 ShareServer(18083)+二维码页，**操作全在手机浏览器** fm.html（浏览/下载/上传/重命名/删除/复制/搜索/编辑/装 APK），带 4 位随机访问码鉴权（重启页面会变）。
- 新增「应用管理」：/api/apps 列出车机应用（第三方/系统筛选+搜索）、op=uninstall 卸载、op=launch 启动。卸载与装 APK 对称：root `pm uninstall [-k]` 静默；免 root 拉系统卸载界面车机点确定。AppManager 静默卸载后二次确认包真没了。
- 二维码页（recv.html + FileShareActivity）改**左右排版**：左二维码右地址，1024x600 车机屏可显示全。已截图确认。
- MuMu 全链路实测：/api/info、/api/apps、免 root 卸载闭环（API 拉起 UninstallerActivity → 点确定 → 包移除）、launch 均通过。
- 关键坑（已写进 README v1.6.15 节）：root ls 必须**尾斜杠**（/sdcard 是软链）；4.4 toolbox ls 目录行无 size 列；su 探测缓存 30s；**MuMu 截图 1080 宽是缩放图，实际 1440x810，input tap 坐标必须按 wm size**（这次差点误判 App 坏了）；MuMu su 管理器不记住授权。
- 待车机实测：扫码 → 手机操作全流程；车机 eng 有 su 则静默卸载/系统目录可用。

- 二维码页滚动修复（用户反馈）：车机 1024x600 下 WebView 只剩 ~260px 高，而 recv.html 二维码按宽度 38% 算 ~380px 高 → 内部滚动。修复：① recv.html 二维码改 **JS 按容器高度自适应**（边长=min(高96%, 宽46%)，overflow:hidden 锁死不滚动）② FileShareActivity 固定元素压缩（日志 96dp→52dp、标题/字号/margin 收紧）。**验证方法：MuMu `wm size 1024x600` 临时覆盖分辨率**（4.4 支持 override），截图确认一屏放下后 `wm size reset`。教训：改车机 UI 必须先 `wm size 1024x600` 再截图，1440x810 下"看着正常"不代表车机不滚。

- ★车机日志分析（用户两份 zip：10-01 与 10-06）：「WLAN速率低→断联」根因基本锁定为**单射频双连**。10-01 时间线：08:48 车机 GO 192.168.49.1（直连中）→ 08:50:15 车机 wlan0 DHCP 到 172.29.200.190（对端 DHCP=172.29.200.143，vendor=ANDROID_METERED，是某台安卓设备的热点）→ 08:52:41 P2P 组地址消失（组被拆）。GO+STA 异信道并发 → MCC 延迟尖刺（亿连 2s ping >200ms×3 → 提示速率低）→ 驱动拆组 → 断联。RF 本身清白：RSSI -39 优秀、0 errs/0 drop、CPU performance 不降频。10-06 快照：车机是**客户端**（p2p-p2p0-2=.64，手机当 GO .1），wlan0 未连任何 AP，链路健康。→ 处置：直连时关掉手机热点 / 车机 WiFi 里取消保存该热点；给 BootTask 加"P2P 组活跃且 wlan0 有 carrier"告警项（待做）。车机无 root（su probe 失败），亿连 /sdcard/logger 不存在、ec.conf 未定制。

- ★对质外部分析（用户贴的）：其核心前提"10-01 亿连不存在"是错的——zip2 top 里 net.easyconn PID 3725（63线程）+ 3785（fg）都在跑，ps 段是被 keep 截断才没显示。10-01 的 192.168.49.1 组归属存疑（车机同时跑亿连和 desay CarLife，两者都能建 GO），但"wlan0 连第三方热点 → 2.5min 后组被拆"的双连时间线与归属无关，仍是唯一实锤的拆组机制。GO 角色两次不同（10-01 GO / 10-06 client）属实但本就是两次独立会话；p2p-p2p0-2 序号=开机后第3次建组，弱证据支持反复重连。
