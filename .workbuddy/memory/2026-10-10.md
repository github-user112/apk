## 追「WLAN 速率低」根因：亿连判定机制实锤（v1.6.24）

**机制（亿连 V7.0.1 反编译实锤，`Yilian/04_文档/亿连V7.0.1_直连低速断连_分析报告.md`）**：
- 文案 `wifi_low_speed_tip = WiFi传输速率低`，弹出点 `f.a.k.l0.p3.w()`。
- 监控线程 `Mirror_Presenter_Ping_Service`（镜像 Presenter `r0.o()`）**每 2 秒 ping 一次对端**，
  `ECSDK.native_ping(ip, 250)`，**单次 RTT >200ms 记 1 次，连续 3 次（约6 秒）弹 Toast**；
  有一次正常就清零 → 弹窗代表「连续 6 秒以上持续劣化」。测的是**时延不是带宽**，文案误导。
- 监控启动点：`f.a.i.i.q.l0()`（startMirror）且 `q.H().name().contains("WIFI")`
  → EC_TRANSPORT_ANDROID_WIFI(2) 覆盖**直连+热点**，**走 USB 永不弹**。
- ★弹窗**不断链**（w()/z() 只操作 Toast + 隐藏 View）→ "先提示后断"是同因两果
  （RTT劣化 + CtrlSocket/DataSocket 超时同时发生）；断链走 native onDisconnect →
  `m.onMirrorDisconnected()` → `g0.i0(4)`。
- 车机端重连很弱：`p3.onMirrorRequestReconnect()` 是**空方法**。

**日志侧佐证**：10-09 日志 wlan0 NO-CARRIER/收发0（无双连）、CPU 996MHz performance/load 0.15
（无降频）、p2p口errs 0 drop 2（空口没丢包）→ 这次 RTT 若超标只能来自
(a) GO 角色本身负担 (b) 空口排队/干扰 (c) 手机侧省电PS模式。

**★能给用户的免 root 缓解手段（按性价比）**：
1. 改通道形态：别用直连，用「手机开2.4G热点→车机连」（车机从 P2P GO 变纯 STA，空口压力减半 + 无双连）。
2. 手机保亮屏对照（息屏 Wi-Fi 进 PS 模式，RTT 直接翻倍，最常见原因）。
3. 降码率：`/etc/ec.conf` 写 `mirror_width=1024 / mirror_height=600`（免重打包、亿连启动热读，
   改完重启亿连 App 生效）——★**但 10-09 日志实锤这台车机无 /etc/ec.conf 且无 root，/etc 写不了**，
   免 root 无法降码率。备选要重打包亿连改 `assets/EcConfig.prop` 的 `MEDIA_LEVEL=0`。
4. 直连必须车机 2.4G 档（5G 档 P2P 监听跑 5G 手机扫不到）。
5. 消掉弹窗没用（它不是断链原因）。

1. P2｜FileMgr 正常启动路径零日志：FLog.log 只在失败分支调用（webview fail/pm install fail），UploadServer.start() 成功只 Log.i 到 logcat、**绑定失败也不落 FLog 不上 UI** → 端口被占用时用户只见"等待接收…"二维码连不上，无从排查。建议 start()/bind 失败走 FLog + Listener 通知 UI。ShareServer(18083) 疑似同款未验证。
2. 环境（非包问题）：MSYS 路径改写打爆 adb shell pm install 的 /data 参数（血泪 8 重演，必须 MSYS_NO_PATHCONV=1 且 push 也要）；adb daemon 每次工具调用被重启 → MuMu connect 与 realme 锁屏每次都得重来，关键操作必须单次调用链完成。
3. 非 bug 确认：ReceiveActivity/P2pGuard not exported 是设计如此，Android 12 下 am start 被拒属正常，App 内部启动不受影响。
4. 升级顺序提醒（远程 memory 已记）：先装 CarFiles 再升 BootTask 1.6.28（1.6.28 起没有 18082 传包通道）。
