## BootTask v1.6.30（vc37，2026-10-12）：直连免打扰改用无障碍自动点弹窗（修 v1.6.29 P0）
**v1.6.29 的「自动同意」是无效功能，写错了。** 外部审查从 MuMu framework.jar 实锤 +
我用 android-all 4.4 全量 jar（含 @hide）复核，三条 API 全不存在：
- `WIFI_P2P_CONNECTION_REQUESTED` 广播 → 不存在（P2P 只有 6 个标准 action）
- `requestGroupInfo(WifiP2pDevice)` → 不存在（只有 `requestGroupInfo(Channel, GroupInfoListener)`）
- `EXTRA_WIFI_P2P_DEVICE` key → 真值 `wifiP2pDevice`，key 也编错
接收器永不触发 + accept 必抛 NoSuchMethodException；不崩（防御好）但功能静默无效。
**根因教训**：注释写"标准做法"但没验证就发版；隐藏 API 断言必须 javap 实锤（android-all jar 比
framework.jar 还严格，含 @hide）。**下条铁律**：任何"框架里应该有的 API"，写之前先
`javap -p -constants -classpath <android-all 4.4 jar> <类>` 查证，查不到就是不存在。
- 本版正解（用户提的无障碍方案，已采纳）：`P2pDialogClicker extends AccessibilityService`，
  收窗口事件 → getRootInActiveWindow 遍历 → 命中同意按钮 performAction(ACTION_CLICK)。
  删掉假接收器 P2pAutoAcceptReceiver + 不存在的广播 action；P2pAutoAccept 退化为开关/计数/状态。

  3 秒冷却 / 全程落日志含未点原因。
- 主界面：开关 + ①去系统设置启用无障碍（系统不给自动开） + ②立刻测试一次 + 状态行
  （已点 N 次/错过 M 次/服务启用态）。
