## REA（Reverse Engineer Anything）工具链落地 + 亿连 V7.0.1 全量分析（2026-10-13）

**REA 装机要点（下次直接用，别重踩）**：
- `sudo npm install --global rea-agents` → `rea` 6.4.0（普通用户装全局会权限报错）
- Android 分析要 **完整 JDK 17+（含 jdk.compiler）**：本机原装只有 JDK 11，另下
  Temurin 21.0.12.1 aarch64 到 `/tmp/opencode/tools/jdk-21.0.12.1+1`（重启会丢，重下即可）
- 引擎 jar：`jadx-headless-mcp-0.7.1-all.jar`（官方审计 sha256
  `6e5eacf5…3ff75`，下载地址写在 REA 源码 `src/android/JadxRelease.ts`）
- 两个环境变量：`REA_JADX_MCP_JAR=<jar 绝对路径>`、`JAVA_HOME=<jdk21>`
- 常用命令：`inspect-android-package` / `search-android-classes` /
  `inspect-android-class` / `inspect-android-method` / `trace-android-references`
- **坑**：内部类名用 `.` 不用 `$`（`ECTypes.ECTransportType`）；
  `trace --method-name` 遇重载方法直接报错（不猜），要换唯一方法名

**分析产出**：`Yilian/04_文档/亿连V7.0.1_REA逆向分析报告.md` + `rea_evidence/`（20 份 Evidence，
commit `c2db58f4` 已推）。核心结论：薄 Java 门面（ECSDK 263 方法/130+ JNI）+ native 协议栈
（libECSDK.so 8MB）；传输枚举 15 种 + 四种 bind 语义；连接核心混淆类 `f.a.i.i.q`（Handler 状态机，
openTransport 只由它内部 handleMessage 触发）；网络共享 = NetLinkService(DNS代理+tun2socks)，
镜像连上按 `MIRROR_CONNECTED_OPEN_VPN` 自动共享；ECOptions 有 `useJavaBindTransport`
（亿连留了 Java 传输后路）/`socketTimeoutPeriod` 可配。

**局限（下一步）**：native 协议栈未反编译 —— REA 的 native provider 要 Ghidra/Hopper/IDA，
本机没装；Ghidra 在 Linux/aarch64 未验证。本次 native 侧只是 `strings` 补充取证（报告里已标注）。
