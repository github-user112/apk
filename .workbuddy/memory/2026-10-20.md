### ★ P0 缺陷：USB 未授权时授权框无限弹窗
- 现象：MuMu 上首次点「USB」标签 → 系统 `UsbPermissionActivity` **每秒弹 1 次**（实测 25s 弹 25 次、累计 178 次），**点「确定」也挡不住**（点完 4 次内又弹），界面被彻底锁死，只能 force-stop。
- 授权过一次后（`dumpsys usb` 出现 `Device permissions: /dev/bus/usb/001/002: <uid>`）**完全正常，弹窗 0 次**，守卫 `hasPermission()` 生效。
- 根因（`smali/a/a/a/a/m/n/c/c.smali` 的 `run()` 扫描循环）：
  - 循环体末尾 `:goto_1a` 处 `Thread.sleep(1000)` 后**无条件** `startActivity(UsbPermissionProxyActivity)`；
  - `hasPermission()==false` 分支只写了一条日志文案：「有线: 弹出系统 USB 权限框…**勾了『默认情况下用于该 USB 设备』才会一劳永逸，否则每插一次都要点**（或靠无障碍服务自动点）」——**开发者知道会重复弹，但没做退避/去重**；
  - 代码里无「已请求过」标志位，也无冷却。
- 附带：`UsbPermissionProxyActivity` 里 `PendingIntent.getBroadcast(this, 0, ...)` **requestCode 固定 0**，4.4 上同 PendingIntent 会被覆盖（复用），多设备场景易互相干扰。
- 修复建议（若要改）：①`c.smali` 加 `lastRequestMs` 静态字段，60s 内不重复 request；②加 prefs「USB 已拒绝过就不再自动弹，只在日志提示手动开」；③requestCode 改为设备 hashCode。
- ⚠️ 这正是 mod1.12「USB 免授权（无障碍自动点）」要解决的问题，但 **2.0 版并没有带上那个修复**（只有 `UsbAccessibilityService` 声明，无自动点逻辑）。

### 环境备忘（新增）
- 本机**没有 aapt**；读 APK 版本号用 `apktool.jar d` 后看 `apktool.yml` 的 `versionInfo`（`tools/apktool.jar` + `tools/jdk-17.0.20.1+1`）。
- 反编译看源码：`java -cp "tools/jadx/lib/*" jadx.cli.JadxCLI -d <out> <apk> --no-res`（单 dex 532 类约 40s）。
- jadx 对「构造器反射/内部类」会丢调用边，**找调用方必须回 smali 搜字符串常量**（本例 `usb_device` / `UsbPermissionProxyActivity`）。
- **MuMu 返回箭头坐标**：横屏 1440x810 在 `(52,55)`；realme 竖屏 1080x2400 在 `(120,240)`。用 `keyevent 4` 对 CarLife 的设置/方控页**无效**（自己吃掉返回键）。
- Python 里 `from _tap import DEV` 会**在 import 时绑定模块常量**，切设备必须在 import 前改 `_tap.DEV` 或自己写函数，别用 `from` 拿设备号。
- realme 上 `pm install` 前台执行会 SIGTERM（挂起），必须写进脚本/后台跑；单次 adb 调用链里 `input keyevent KEYCODE_WAKEUP` + `wm dismiss-keyguard` 必须带。
