## ★ 结论：CarLife 直连在官方 0.2.7 里被硬编码关闭（不是配置问题）
证据链（smali 级，4 处联动）：
1. `zb1.J()`（首页连接模式读取）：读 prefs `HOME_CONNECT_MODE`，**若 ==2(直连) 则强制 `zb1.N(0)` 回退有线**，
   日志原文 `direct entry disabled, coerce home mode DIRECT -> WIRED`。
2. `zb1.N(I)`：写 `HOME_CONNECT_MODE` + `HOME_CONNECT_WIRED`（p0==0 时 WIRED=true）。
3. `u00.b(I)`（initConnectType）：`if-eq p0, 0x2 → :cond_2`，**cond_2 分支把目标主机设成 `127.0.0.1`**、
   端口 0x1c20=7200 → 直连被改成连本机回环，必然连不上。
4. `u00` 直连分支日志：`【直连连接】直连入口已关闭（DIRECT_MODE_ENABLED=false），拒绝启动`。
- **实测复核**（MuMu）：手动 `sed` 把 prefs `HOME_CONNECT_MODE` 改成 2 → 启动 App 后
  自动被改回 **0** 并写 `HOME_CONNECT_WIRED=true`，界面回到「有线」页签。**强制开启无效**。
- UI 上「默认连接方式」弹窗**只有「有线/热点」两项**，无线直连选项不出现。
- 蓝牙侧：`BluetoothAdapter.enable()` 全包仅 4 处 —— `DiPlayActivity`(CarPlay 侧)、`dq`(DiPlay 侧)、
  `bj`/`l51`；**CarLife 侧 0 处**。CarLife 直连仍走 `xa0` 里的老路：
  遍历 `getBondedDevices()` → 按 `CONFIG_TARGET_BLUETOOTH_NAME`(默认 XM13) 过滤 → RFCOMM 握手拿 IP。
  → **你车机「Android 蓝牙起不来」这个堵点它一点没解**，反而比 mod1.29 还弱。
- 结论：**对你车机毫无直连价值**，热点模式 9-24 实测 100% 通，别折腾。

## 有用功能盘点（对车机有价值的）
- **按键映射**（设置→按键）：厂商按键广播协议选择 + 逐键映射（MEDIA_NEXT/PREV/PLAY/STOP、DPAD_OK/CALL/ENDCALL/HOME…）
  + **按键检测**（按一下看收到什么）+ **导入/导出** + 恢复默认。比我们 mod1.x 的方控全。
- **权限页**：读取存储/录音/读取电话状态/定位 + **USB权限自动授权**（无障碍自动点系统授权框）
- **USB 设备页**：插设备后扫描、U 盘可忽略、设备列表/恢复
- **车机能力检测**：一页看全连接/权限/显示/音频/按键/能力
- 其它：DiPlay 侧的 CarPlay VPN、仪表盘地图（AdbClusterActivity）、热点加入修复
  （HotspotJoinRepairMain，需 root/uid2000，SDK≥33）、CarPlay 方向盘按键无障碍（WheelKeyService）
- **直连相关配置项存在但无效**：`CONFIG_WIFI_DIRECT_NAME`(默认 DIRECT-CARLIFE)、
  `CONFIG_TARGET_BLUETOOTH_NAME`(默认 XM13)、`CONFIG_WIFI_DIRECT_TYPE`、
  「车机端直连名称」「手机端蓝牙名称」设置项 —— 代码在，入口被关。

## 踩坑
- apktool 解包要 `-s` 才快；但要读 smali 逻辑必须完整解包（不 `-s`），单 dex 2585 类。
- 资源 ID 被 R8 改名成 `org/conscrypt/R.java` 里的常量，`grep strings.xml` 找不到引用类，
  须用 `grep -rln "0x7fXXXXXX" smali/` 反查。
- 混淆类归属判定：`grep -c "com/shilapi/xcertplay" smali/X.smali` 判 DiPlay 侧，
  `grep -c "com/baidu/carlifevehicle"` 判 CarLife 侧。
- MuMu 返回键会误触「退出应用」确认框；设��页内导航要用左上角箭头坐标 (52,55)。
- `su -c` 改 prefs 会被 App 启动时的迁移逻辑覆盖（这正好是反证直连被禁的手段）。
