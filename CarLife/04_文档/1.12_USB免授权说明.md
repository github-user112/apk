# CarLife 车机端 1.12 —— USB 免弹窗授权

> 针对问题：1.11 只把 USB 权限弹窗从「每秒一次」降到「5 秒一次」，本质还是要用户点。
> 本文说明弹窗的**真正根因**，以及 1.12 的四层免授权方案。

---

## 一、弹窗到底是谁弹的

`UsbAccessoryScanner.run()` 每秒一轮扫 `getDeviceList()`，发现设备且
`hasPermission()` 为假，就启动 `UsbPermissionProxyActivity` →
`UsbManager.requestPermission()` → 系统弹授权框。

**根因不在频率，在 Manifest。** AOSP 的 `UsbHostManager.usbDeviceAdded()` 大致是：

```java
ArrayList<String> matches = getDeviceMatches(device, intent);   // ← 内部 queryIntentActivities()
if (matches.size() > 0) {
    for (String pkg : matches) {
        mSettingsManager.grantDevicePermission(device, uid);     // ★ 系统自动授权，不弹框
        intent.setComponent(...); mContext.startActivity(intent);
    }
} else {
    // 没有 Activity 声明匹配的 device_filter → 弹权限框
}
```

`queryIntentActivities()` **只认 Activity**。CarLife 把
`USB_DEVICE_ATTACHED` 只挂在 `BroadcastReceiver`（`BroadcastActionReceiver`）上，
所以 `matches` 恒为空 → 系统永远走「弹框」分支。

顺带一提：`res/xml/device_filter.xml` 原本就是空的 `<usb-device />`（全通配），
资源一直都在，只是挂错了组件。

## 二、1.12 的四层免授权

| 层 | 补丁 | 原理 | 需要什么 | 覆盖率 |
|---|---|---|---|---|
| 1 | **patchQ** 系统自动授权 | 补 `UsbAutoGrantActivity` 声明 intent-filter + device_filter，系统插入设备时自动 `grantDevicePermission` | 无 | 冷插入场景 |
| 2 | **patchP** 静默 openDevice | USB 权限是 App 侧「君子协定」：`hasPermission()` 只是查记录表，而真正打开设备的 `openDevice()` 跨进程调到 `UsbService`，**Android 4.x 不校验那张表** | 无 | 主要手段 |
| 3 | **patchR** 弹窗前先静默 | 即使走到 `UsbPermissionProxyActivity`，也先试一次静默 open，成功就 `finish()` 不弹 | 无 | 兜底 |
| 4 | **MANAGE_USB** priv-app | Manifest 已声明该权限（`signature\|privileged`），装到 `/system/priv-app` 后 UsbService 完全放行 | 车机 root | 100% |

### patchP 详解（核心）

把 `run()` 里的 `hasPermission()` 换成了 `f.c()`，三级判定：

```
1) 系统里已有授权记录   -> 放行
2) 之前静默成功过 (q)   -> 放行
3) 静默 open+claim+close 试探 -> 成功则置 q 并放行
   三级全失败           -> 返回 false，退回原来的弹窗路径
```

**关键：这是安全降级。** 万一某台车机的 ROM 给 `openDevice()` 也加了权限校验，
`f.e()` 会抛异常被吞掉，返回 false，行为退回 1.11（5 秒一次弹窗）——不会更糟。

### patchQ 的副作用

`UsbAutoGrantActivity` 是透明主题、立即 `finish()`，插 U 盘也会被拉起一次
（无界面、无感知）。如果车机常插 U 盘介意这点，可以从 Manifest 里删掉这个
Activity，只保留 patchP。

## 三、车机（Android 4.4.2）上怎么验证

```bash
# 装包
adb install -r -d "CarLife4.0车机端个人修改版1.12_USB免授权.apk"

# 插上手机，抓 USB 链路日志
adb logcat -c
adb logcat -v time | grep CarLifeUsb
```

对照日志判断走了哪条路：

| 日志 | 含义 | 结论 |
|---|---|---|
| `silent openDevice OK -> USB auto-granted, no dialog` | 静默打开成功 | ✅ 全程零弹窗 |
| `USB_DEVICE_ATTACHED: system granted permission, no dialog` | 系统自动授权 | ✅ 零弹窗（层1 生效） |
| `MANAGE_USB granted (priv-app)` | priv-app 特权 | ✅ 100% 免授权 |
| `silent openDevice blocked -> fall back to permission dialog` | 静默被 ROM 拦了 | ⚠️ 退回弹窗，走层3/层4 |
| `usb permission request allowed`（反复出现） | 仍每 5 秒请求一次 | ❌ 前三层都失败，需 priv-app |

## 四、都不行时的最后手段

### 4.1 装成系统特权应用（需 root）

```bash
bash "C:/PJGG/apk/CarLife/03_构建脚本/install_priv_app.sh"
# 回滚：bash ... install_priv_app.sh --uninstall
```

脚本会 `adb root` → 挂 `/system` 可写 → 推到 `/system/priv-app/CarLife/` → 重启。
之后 `MANAGE_USB` 生效，UsbService 对 `openDevice` 完全放行。

### 4.2 无障碍自动点击（需开一次）

CarLife 自带 `UsbAccessibilityService`（在设置里的名字是「USB设备连接自动授权」），
它会监听窗口变化，找到「确定」/「允许」按钮自动点。

**只需在车机「设置 → 辅助功能」里手动开启一次**，之后所有 USB 授权框自动点掉。
适合既不想 root、ROM 又拦了静默 open 的情况。

## 五、Android 4 兼容性

新增代码只用了：

- `UsbManager.openDevice / claimInterface / close`（API 12+）
- `Context.checkCallingOrSelfPermission`（API 1）
- `Activity.finish()`（API 1）

未引入任何 Java 8 / lambda 语法。`minSdk=16` 未改动。

**smali 层面两个坑（本次都踩了）：**

1. smali 汇编器硬限制 `invoke-*` / `if-*` 只能用 **v0–v15**。第一版想用 v17/v18
   暂存 UsbManager，直接编译失败。最终改成「把决策逻辑收进静态方法，调用点只替换
   两行」，一个寄存器都不加。
2. Dalvik 校验器拒绝「汇合点寄存器类型不一致」。`f.e()` 的 try 块内不放分支、
   catch handler 单独 return，避开所有汇合点。

`verify_dalvik_合并点检查.py` 对 `_w112` 跑过，34 个方法、零冲突。
