## 一、去掉开机引导界面（本次改动）

### 原来打开 CarLife 会经过两屏

| 屏 | 类 | 布局 | 耗时 |
|---|---|---|---|
| ① Logo 启动页 | `a.a.b.n.r`（LaunchFragment） | `frag_launch.xml`（纯 logo + copyright） | **2000ms** |
| ② 用户引导 ViewPager | `a.a.b.n.u`（UserGuideFragment） | `fragment_user_guide.xml` + `DirectionViewPager` | 手动翻完才进主界面 |

### 触发逻辑（改之前）

```
CarlifeActivity.onCreate() -> k.a(LaunchFragment)
LaunchFragment.onCreateView():
    first_install_key = prefs.getBoolean("first_install_key", true)
    if (first_install_key)   -> delay 2000ms -> 发消息 2009  -> UserGuideFragment
    else                     -> delay 2000ms -> 发消息 2005  -> 主界面
    prefs.first_install_key = false
```

### 改法（patchT / patchU，只动 `a/a/b/n/r.smali` 两处）

1. `if-eqz p1, :cond_2` → **`goto :cond_2`**
   首次安装判断被短路，**永远走 2005（主界面）**。
   UserGuideFragment 变成死代码（文件保留不删，想回滚把 `goto` 改回 `if-eqz` 即可）。
2. `const/16 p2, 0x7d0`（2000ms）→ **`const/16 p2, 0x64`（100ms）**
   Logo 页几乎一闪而过。留 100ms 是让 Fragment 事务提交完，直接给 0 在部分车机会闪黑屏。

不新增方法、不新增寄存器、不引入新 API，Android 4.4 无风险。

## 二、直连流程现在和亿连一样了吗？—— **没有，也不可能完全一样**

分三类说：**已经对齐的机制**、**结构性对不齐的**、**还能补但还没补的**。

### A. 已经对齐的（1.10→1.12 补的）

| 维度 | 亿连 V7.0.1 | CarLife 1.13 |
|---|---|---|
| 自己建 P2P 组 | 有 createGroup 路径 | ✅ patchD：8s 无组则自举建组当 GO |
| 失败分级 | 各回调分级处理 | ✅ patchH：reason=1 降级 / =2 先 removeGroup |
| 重试节奏 | 120s 周期重扫 | ✅ patchH：快试 6 次退避 4→14s，再慢扫 12 轮×30s |
| 断线自愈 | clearLocalServices → 重新 addLocalService | ✅ patchK：重新 arm 自举器（15s 去抖） |
| 断开清理 | 三连：clearLocalServices + stopPeerDiscovery + removeGroup | ✅ 已补齐 |
| 组播锁 | 22 处，非引用计数 | ✅ patchI/M：改为 setReferenceCounted(false) |
| 发现风暴 | 无 | ✅ patchF-3：永久抑制重排（实测每秒 44 条 → 0） |
| USB 权限弹窗 | 静态防重入 | ✅ 1.11 去抖 + **1.12 四层免授权** |

### B. 结构性对不齐（**改不了，别再往这个方向使劲**）

| 差异 | 亿连 | CarLife | 为什么改不了 |
|---|---|---|---|
| **自举手段** | mDNS 网内自举，**不依赖蓝牙**（4.4.2 上 BLE 直接 return） | **蓝牙 RFCOMM 带外自举**（SPP UUID 00001101），蓝牙断则全链路终止 | 手机端 CarLife App 是百度发布的二进制，我们**只能改车机端**。两端协议必须配套，单方面改车机没用 |
| **车机角色** | TCP **服务端**（ServerSocket ×12，端口由 mDNS 动态告知） | TCP **客户端**（全 dex 只有 1 处 `new Socket`，**0 处 ServerSocket**），host+port 只能来自蓝牙 | 同上，协议层决定 |
| **GO 角色** | 车机 GO / 手机 GO **双向兼容** | 固定手机为 GO（192.168.49.1） | 车机端地址来源是蓝牙下发的，改这个等于改协议 |
| **自己开热点** | 支持 `setWifiApEnabled` | 不支持，只能被动等 UDP 广播 | 需要系统权限，且 CarLife 没这条代码路径 |

> ⚠️ 一个要澄清的点：1.11 加的 DNS-SD（`addLocalService` + `WifiP2pDnsSdServiceInfo`）
> **不等于**亿连的 jmdns 全网广播。P2P DNS-SD 只在 P2P 组内有效，且需要**对端主动发
> `addServiceRequest` 去查询**——CarLife 手机端不会去查。所以它对"让手机找到车机"
> **很可能没有实际帮助**，只对第三方 mDNS 浏览器可见。真正的网内自举做不了（见上表第一条）。

### C. 还能补、但还没补的（按收益排序）

| # | 缺口 | 亿连做法 | 改动面 | 收益 |
|---|---|---|---|---|
| 1 | **心跳探活** | socket `:10922`，`setSoTimeout(3000)`，**2s 一次，失败 3 次判离线** | 中（要挂在传输层 tick 上） | **最高**：现在是"连上就不管了"，手机走了车机不知道 |
| 2 | **周期重扫是有限次** | **无限** 120s 一轮 | 小（patchH 把 12 轮改成无限） | 高：车机是常电设备，现在约 7 分钟后彻底放弃 |
| 3 | IP 就绪等待 | 轮询 `sleep(500)` 直到拿到合法 IP（正则排掉 0.0.0.0） | 小 | 中：P2P 组刚形成时 IP 常未就绪 |
| 4 | 多网卡遍历 | 遍历 `NetworkInterface` 按白名单逐个注册 | 中 | 中 |

## 四、回滚方法

`smali/a/a/b/n/r.smali` 里把

```
    goto :cond_2
```

改回

```
    if-eqz p1, :cond_2
```

并把 `const/16 p2, 0x64` 改回 `const/16 p2, 0x7d0` 即可恢复原行为。
UserGuideFragment（`a/a/b/n/u.smali`）一直保留在包里，不会被误删。
