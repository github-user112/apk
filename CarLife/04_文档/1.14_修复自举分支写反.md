# 1.14 修复直连自举器分支写反（MuMu 实测发现）

> 版本：`CarLife4.0车机端个人修改版1.14_修复自举分支.apk`
> versionCode `114` / versionName `mod1.14`（基线 1.13 = 113）
> 日期：2026-09-22

---

## 一、Bug 是怎么被发现的

1.13 装进 MuMu（Android 4.4.4）实测，引导页确认消失、零崩溃，但自举器日志暴露异常：

```
12:43:17 CarLifeP2PBoot: P2P group detected, bootstrap idle
```

**MuMu 根本不支持 P2P（`P2pNotSupportedState`），不可能有组。**
"有无组"的判断方向写反了。

## 二、两处分支写反（patchH 重写 j$b/j$a 时引入的回归）

### bug1：`j$b.run()` 有无组判断

`i.f` 的语义（`i.smali` 333/388/467 行）：

| 事件 | f 值 |
|---|---|
| `WifiP2pInfo.groupFormed == true` | **1（有组）** |
| `groupFormed == false` | 0 |
| `WIFI_P2P_STATE_CHANGED` 断开 | 0 |

原代码 `if-eqz v1, :formed`：f==false（无组）→ 判"有组"→ 空闲。

**后果**：车机上正常无组状态**永远不 createGroup**（patchD 完全失效）；
而已有组时反而去 createGroup → 必然 BUSY。这也解释了早期真机 createGroup BUSY 的现象。

修复：`if-eqz v1, :formed` → **`if-nez v1, :formed`**

### bug2：`j$a.onFailure(reason)` 失败分级对调

原代码实际行为：

| reason | 原行为 | 正确行为 |
|---|---|---|
| 1 = P2P 不支持 | 走 "BUSY → removeGroup + 退避重试" ❌ | 放弃、提示降级 |
| 2 = BUSY | 走 "UNSUPPORTED → give up" ❌ | removeGroup + 退避重试 |
| 0 = ERROR | give up | （保守）give up |

修复：第一个比较常量 `0x1` → `0x2`；删除 `:check_busy` 内的二次比较
（能走到那里只剩 reason==2，无条件 removeGroup 后退避）。
