# 1.16 日志下载功能说明（扫码下载车机本次日志）

> 版本：`_w115` → `_w116`，versionCode 116 / versionName `mod1.16`
> 产物：`CarLife/05_产物/CarLife4.0车机端个人修改版1.16_日志下载.apk`
> 验证：MuMu 4.4.4（API 19）全链路实测通过，见 §6

---

## 1. 一句话

车机上打开「CarLife 日志下载」界面 → 屏幕显示二维码（内容是 `http://<车机IP>:18080`）→
手机接入同一网络后扫码 → 浏览器打开车机内嵌的 HTTP 服务 → 列出日志文件、单个下载或整包下载。

参考对象是 **CarLife 5+ 车机端**（`com.muyetuge.carlifevehicle`）的同名功能。

---

## 2. 5+ 版是怎么做的（参考实现）

| 环节 | 5+ 的实现 | 位置（5+ 反编译） |
|---|---|---|
| HTTP 服务 | 内嵌 **NanoHTTPD** | `q8/l`（= `NanoHTTPD`，含 `ServerSocket`、`Pattern`、`Logger`） |
| 业务 handler | 继承 NanoHTTPD 的定制类，构造参数 = (目录名, 允许扩展名) | `l8/p` |
| 日志服务实例 | `new l8/p("log", "")` | `d8/j;->b` |
| 端口 / URL | `"http://" + 本机IP + ":18080"` | `l8/p;->j()` |
| 启停 | `k()` = `NanoHTTPD.start()`，`l()` = 停止 | `l8/p;->k()/l()` |
| 文件列表 | `getExternalFilesDir(null)/log` 下 `listFiles()`，按时间排序取前 5 | `l8/p;->i()` |
| 网页 | `assets/download.html`（列表页）/ `upload.html`（上传页） | assets |
| 二维码 | 界面用二维码显示 URL，配套上传页 | `d8/a.smali` 调 `l8/c;->a(String)Bitmap` + `assets` |

> 5+ 的日志目录是 `getExternalFilesDir(null)/log`（`/sdcard/Android/data/<pkg>/files/log`）。

**为什么不能直接搬**：5+ 的 UI 是 Jetpack Compose（`d8/*`），二维码走 Compose 第三方库
（`m5/e` 纠错级别枚举 / `l6/b` 样式），NanoHTTPD 也依赖它自己的工具链。1.6 是纯 smali 的
老式 Android 工程（minSdk 16），全部搬进来等于重写半个 App。

---

## 3. 1.6 的落地方式（零第三方依赖）

只借鉴 **思路**，实现全部自己写：

```
LogDownloadActivity（车机界面）
  ├─ onStart()  → LogHttpServer.start()      绑 0.0.0.0:18080，起 accept 线程
  ├─ onStop()   → LogHttpServer.stop()       关 ServerSocket，放端口
  ├─ WebView 渲染 assets/logxfer/logxfer.html#<url1>,<url2>
  │      └─ qrcode.js（纯算法）把每个 URL 画成二维码
  └─ 底部 TextView 兜底显示 URL（WebView 不可用时仍可手输）

LogHttpServer（内嵌 HTTP/1.1，手写 ServerSocket）
  GET  /          → 扫描日志目录，输出文件列表页（HTML）
  GET  /f/<idx>   → 下载第 idx 个文件（Content-Disposition: attachment）
  GET  /all.zip   → 打包全部（临时 zip，发完即删）
  GET  /favicon.ico → 204
```

### 关键设计取舍

| 决策 | 原因 |
|---|---|
| **不用 NanoHTTPD** | 1.6 只依赖 JDK 的 `java.net`，一个类搞定；NanoHTTPD 得整包搬 |
| **二维码交给 WebView + qrcode.js** | 在 smali 里手写 QR 编码/纠错/掩码不现实；`qrcode-generator`（MIT，56KB 纯 JS）用 `createImgTag()` 输出 base64 GIF，老 WebView 也能渲染（SVG `innerHTML` 在老 Chromium 上有风险，只作兜底） |
| **不用 Compose/XML 布局** | 界面全部代码构建（`LinearLayout` + `WebView` + `TextView`），不新增任何 `res` 资源 id，避免动资源表 |
| **Java 源码 + 转 smali** | 见 §5，用 `javac → D8 → apktool 反汇编` 产出 smali，比手写 4000 行 smali 可靠得多 |
| **排序用冒泡** | 省掉 `Comparator` 匿名内部类，少一个 smali 类、少一处校验器风险 |
| **服务串行处理** | 单线程 accept + 处理，不做并发，避免文件列表被并发改写 |

### 日志来源（多目录扫描，去重，按修改时间倒序，最多 20 个）

| 目录 | 依据 |
|---|---|
| `<getFilesDir()>/log` | **车机 4.4.2(API19) 的实际落点**：`a/a/a/a/a/e.smali` 里 `SDK_INT > 21` 才用外部目录，否则用 `getFilesDir()`；日志组件 `a/a/a/a/n/g` 文件名 = `<日期>.log` |
| `<getExternalFilesDir(null)>/log` 及根 | API>21 的落点（与 5+ 一致） |
| `/sdcard/BaiduCarlife` | `a/a/a/a/l/c.smali` 的 `c` 字段常量，落 `<yyyyMMddHH>_Carlife.log` |
| `/sdcard/Android/data/com.baidu.carlifevehicle/files/log`、`/storage/sdcard0/BaiduCarlife` | 兜底 |

只收 `.log / .txt / .gz / .zip` 且非空文件。

> `构建日志下载smali.py` 的原理：`javac`(JDK17, `-source/-target 8`) → **D8**(`--min-api 16`) 产出
> `classes.dex` → 塞进一个现成 APK 当 `classes9.dex` → `apktool d` 反汇编 → 取出 smali。
> 之所以绕这一圈：`apktool.jar` 里的 baksmali 是**被裁剪过的 API**，没有 CLI 入口。
>
> ⚠️ 本机 pip 装不了包（`opencv`/`zxing` 均失败，直连与清华源都不行），
> 需要 Java 侧工具时优先走 Maven Central（可访问）+ `curl`。

> 网络路径说明：MuMu 是 QEMU slirp，宿主机访问不了 guest 的 `10.0.2.15/10.0.3.15`，
> 因此用 `adb forward tcp:18080 tcp:18080` 把车机端口映射到本机再 curl ——
> **等价于手机扫码后直连车机 18080**，只是换了一条物理链路。

### 6.3 验证时踩到的 curl 坑

WorkBuddy 沙箱里 `http_proxy=http://127.0.0.1:50414`，直接 curl 会走代理并返回
`502 Bad Gateway / upstream connect failed`。本地回环必须加 `--noproxy '*'`。

### 6.4 未实测项（**别当成已验证**）

1. **真手机扫码**：验证用的是"截图 → zxing 解码 → 按解出的 URL 下载"，等价但非真实相机扫码。
2. **真实车机 4.4.2 上的网卡 IP**：MuMu 报的是 QEMU 网段；车机直连时应为 `192.168.49.1`
   （GO 默认网关，代码里也是这个兜底值），热点模式下应是手机分配的 `192.168.x.x`。
3. **车机 ROM 若精简了 WebView**：二维码不会显示（`new WebView()` 抛异常被 catch），
   此时退化为底部纯文字地址，功能仍可用但需要手输。MuMu 有 WebView，实测走的是正常路径。

## 7. 使用方式（车机侧入口）

1. 车机桌面/应用列表里点 **「CarLife日志下载」**（1.16 起是一个独立 LAUNCHER 图标）。
2. 也可用 adb / 其他 App 显式拉起：
   `am start -n com.baidu.carlifevehicle/.logxfer.LogDownloadActivity`
3. 界面出现二维码后，手机接入**与车机相同的网络**（直连时是车机热点，或两者同连一个 WiFi），
   扫码 → 浏览器打开 → 点文件下载，或点「打包下载全部（zip）」。
4. 离开页面（返回键/切走）服务自动关闭，端口释放。

## 8. 本版新增的两个坑（已固化）

### 8.1 Git Bash 把 robocopy 的 `/E` 改写成 `E:/`（**构建直接失败**）

```
错误: 无效参数 #3:“E:/”
```

MSYS 的参数路径转换会把以 `/` 开头的开关当 Unix 路径。build.sh 里 robocopy 的输出被
重定向到 `/dev/null`，所以只看到 `!!! 复制失败: ...apktool.yml 不存在`，极难归因。
**修法**：build.sh 顶部已加

```bash
export MSYS_NO_PATHCONV=1
export MSYS2_ARG_CONV_EXCL='*'
```

并补了 robocopy 返回码检查（`>7` 视为失败）。**同样的坑也会打 adb**：
`adb push x.apk /data/local/tmp/y.apk` 会把设备路径改写成
`C:/.../PortableGit/.../data/local/tmp/y.apk` → `INSTALL_FAILED_INVALID_URI`。
调 adb 之前也要带这两个环境变量。

### 8.2 `onDestroy` 在 4.4 上不保证被调用

用 `onCreate/onDestroy` 启停 HTTP 服务时，实测按返回键退出本页后
Activity 只是 `stopped`（退到了 `CarlifeActivity`），**`onDestroy` 没被调用**，
于是 18080 一直被占着。改成 **`onStart` 起 / `onStop` 停** 后行为正确。
