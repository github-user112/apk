## 1. 修 setDeviceName 分支极性（Bug，1.11~1.22 全中）

### 现象 / 根因

`smali/a/a/a/a/m/m/d/i.smali` 里把 `setDeviceName` 的门槛写成了：

```smali
# 修复前（错）
if-lt v2, v1, :p2p_name_done    # name.length() < minLen 才设置 —— 逻辑反了
```

源流是早期 `历史_patch_v3.py` 写死反了极性，之后 `_w111~_w122` 逐树继承。
4.4 上真正的 P2P 设备名设置**从未执行**，一直靠 `WIFI_P2P_THIS_DEVICE_CHANGED_ACTION`
广播兜底（1.15 的 `m.m.d.m`），所以不阻断连接，但 `createGroup` 后的名字对齐不可靠。

### 修复

```smali
# 修复后
if-ge v2, v1, :p2p_name_done    # name.length() >= minLen 才跳过（长度足够则不改名）
```

- 锚点标签 `:p2p_name_done` 不动；调用体不动。
- 影响面：`i.smali` 单文件，其余树不回改（一版一树约定）。

## 2. 心跳周期 2s → 1s（对齐 5+）

| 项 | 1.22 及以前 | 1.23 |
|---|---|---|
| 发包周期 `f$a` / `a(d)` | `0x7d0` = 2000ms | `0x3e8` = **1000ms** |

| 协议号 | `0x20002` | 不变 |

未动控制流，只改 `f.smali` 两处常量 + 日志串 + `f$a.smali` 的周期读取路径（自检确认超时仍在 `f$a` 的 `0x7530`）。

## 3. 失败分级透出界面（对齐 5+ `m7/e0` 提示文案）

### 通道

复用已有 `ConnLog` 日志区（主界面可见），**不新开 Dialog、不新占寄存器**（血泪 12）。
`ConnLog` 追加 4 个零参/单参静态方法：

| 方法 | 触发点 | 文案 |
|---|---|---|
| `logP2pUnsupported()` | `j$a.onFailure` reason≠2 | 不支持WLAN直连 |
| `logP2pBusy()` / 经 `logP2pCreateFail(I)` | `j$a.onFailure` reason==2 | 系统繁忙 |
| `logP2pDiscoverFail(I)` | `h.onFailure` 入口（valueOf 覆盖 p1 之前） | 无法搜索(错误码:N) |
| `logP2pCreateFail(I)` | `j$a` 两处分支 | 按 reason 映射 |

### 与 5+ 的差异（刻意）

- 5+ `m7/e0` 是独立失败界面；我们只打到 **日志行**（车机上用户也看得到，零 UI 面风险）。
- reason 语义按**本项目既有约定**（1=不支持，2=BUSY），与 5+ 控制流分级可能不完全一致，**不改控制流**。
