## 一、P0：reason=0（ERROR）被当成「驱动不支持」永久放弃

### 现象推演

`m.m.d.j$a` 是 P2P 自举器里 `createGroup()` 的 `ActionListener` 回调。
`WifiP2pManager` 的失败原因语义是：

| reason | 常量 | 含义 | 该不该重试 |
|---|---|---|---|
| 0 | `ERROR` | 内部/临时错误 | **该重试** |
| 1 | `P2P_UNSUPPORTED` | 驱动/固件不支持 | 不该（重试无意义） |
| 2 | `BUSY` | 状态机被占 | 该（清干净再试） |

1.14 之前判定写成 `if-eq p1, 0x1`，1.14 修成 `0x2` 之后实际语义变成：

```
p1 == 2 (BUSY)      -> removeGroup + 退避重试     ✅
p1 != 2（含 0、1）  -> 当作 UNSUPPORTED 永久放弃  ❌
```

也就是说 **reason=0（临时错误）会被 `j.b()` 彻底 disarm**：清锁、清服务、清组、
`h=false`、静态开关 `n=false`，并且**永不重试**。车机上「直连偶尔失败就只能切热点 /
重新开关 WiFi」很可能就是这一条。

### 修法：三分，且只有 reason==1 是死路

```
1 = P2P_UNSUPPORTED -> 放弃（logP2pUnsupported + j.b() disarm）  ← 唯一死路
2 = BUSY            -> removeGroup + 退避重试
0 / 其他未知值      -> 退避重试（不做 removeGroup）
```

未知值按 ERROR 处理而不是放弃：**永久放弃的下限太惨**（链路彻底静止），
而多试几次的代价只是几秒退避。

### 实现细节：为什么把退避抽成 `j.d()V`

原实现的 `:backoff` 标签由「BUSY 分支 fall-through」独占。三分之后会有两个前驱
（BUSY 与 ERROR）汇入同一标签，而两处到达时 `v0` 的类型不同（一个是 `j` 引用、
一个是 `int` 常量）—— 这正是 1.18 在 ART 上被拒类的同一类问题（血泪第 11 条）。

所以把退避逻辑抽成 **`j.d()V`**（新增，无 try/catch、无参数），
两个分支各自 `invoke-virtual {v0}, ...->d()V` 后直接 `return-void`，
**彻底消除跨分支的寄存器合并**。

### 极性（写反过一次，已修）

| 指令 | 含义 | 结果 |
|---|---|---|
| `if-ne p1, v0(1), :not_unsupported` | p1 != 1 则跳走 | p1==1 fall-through → 放弃 ✅ |
| `if-ne p1, v0(2), :error_retry` | p1 != 2 则跳走 | p1==2 fall-through → BUSY ✅ |

> ⚠️ 第一版把第二条写成了 `if-eq`（**相等则跳**），会把 BUSY 和 ERROR 整个对调。
> 血泪清单第 4 条再次应验。补丁脚本已加针对助记符的断言：
> 出现 `if-eq p1, v0, :error_retry` 直接报错退出。

### 界面提示同步

`ConnLog.logP2pCreateFail(I)` 原来只有 1/2/其他三档，reason=0 会落到
「⚠ 操作失败，请检查网络设置」（听着像死路）。1.28 新增 `logP2pError()`：

- reason=0 → `⚠ 直连建组失败(系统内部错误)，正在自动重试`
- 其他未知值 → 仍走 `logP2pNetFail`

## 二、顺带修：DNS-SD 本地服务从 1.15 起根本没发布成功

MuMu 日志里一直有这两条：

```
W/dalvikvm: VFY: unable to resolve direct method 650: La/a/a/a/m/m/d/j;.c ()V
E/CarLifeP2PBoot: addLocalService failed (ignored)
```

根因：`j.a()` 里调用 `c()V`（发布 DNS-SD 服务）用的是

```
invoke-direct {p0}, La/a/a/a/m/m/d/j;->c()V     # ❌
```

而 `c()V` 的声明是 `.method public final c()V` —— **`public final` 不是 private /
构造函数，`invoke-direct` 解析不到它**。运行时解析失败抛异常，被 `:catch_2` 吞掉，
日志上就只剩一句 "addLocalService failed (ignored)"。

改成 `invoke-virtual {p0}, ...->c()V` 即可。

**影响**：patchI（1.15 移植的「手机不依赖蓝牙也能发现车机」的 DNS-SD 发布）
在此之前一直是空转的。修好后车机上应能看到

```
D/CarLifeP2PBoot: local service published (_presence._tcp, instance=CarLife-HU)
```
