## 2. 那这一版还改什么

蓝牙硬件/ROM 的事 App 改不了，但 **1.22 的 BtGuard 没本事说清到底是哪种情况** ——
只会反复打「未开启，第 N/30 次」，看不出 `state` 是 OFF 还是 TURNING_ON，
也看不出 `enable()` 到底返回 true 还是被 ROM 拒了。日志拿到手依然无法定案。

### 改动清单

| # | 改动 | 作用 |
|---|---|---|
| 1 | **深度诊断行** | `state` 码(10/11/12/13/15) + isEnabled + 地址/名 + 已配对数 + `enable()` 返回值 + 异常 + `Settings.Global(bluetooth_on)` + 两条获取路径是否同一对象 |
| 2 | **双路径开启** | `BluetoothManager.getAdapter()` 那条 + `getDefaultAdapter()` 都 enable 一次 |
| 3 | **TURNING_ON 不打扰** | state=11/14 时不再重复 `enable()`，免得打断状态机 |
| 4 | **最后一招** | 等 12s / 30s 还不开 → 试着把 `Settings.Global(bluetooth_on)` 写成 1（部分 ROM 拿它当闸门，enable() 被吞；无权限只记一行，不赌） |
| 5 | **30s → 45s** | 车机蓝牙上电确实慢 |
| 6 | **判死一次就记住（sDead）** | 消除「等 30s → 放弃 → `d$c` 重试 → 再等 30s」的空转；蓝牙一旦真开起来立即恢复 |
| 7 | **放弃时给确定性结论** | 明确告诉用户：直连必需蓝牙 → 二选一（系统设置开蓝牙 / 改点热点页签） |

★ **关键：`onSkipDecision(ZLjava/lang/Runnable;)Z` 签名没变**，
`d/a.smali` 的插桩点一行都不用动 —— 本版**零手工 smali 编辑**，
改动全部在 `logxfer_src/java/.../BtGuard.java`，走既有的 javac→D8→apktool 产线。

## 3. 真机验证（realme X7 Pro / Android 12 / ART）

> 按「血泪 11」：新写/改动的 smali 必须至少在一台 ART 设备上跑一遍启动。

| 场景 | 结果 |
|---|---|
| 蓝牙开启时冷启动 | 0 崩溃、0 VerifyError；直接进握手分支 |
| `svc bluetooth disable` 后冷启动 | **自愈生效**：`enable()=true` → 1s 后 `✔ [蓝牙] 已开启, 继续带外握手` |
| 蓝牙刚 disable 的瞬间（状态机还在关） | 正确打出 `enable()=false`，下一轮读到 `state=11(TURNING_ON) bluetooth_on=1` 并**停止重复 enable** |

真机实际输出（这就是新诊断的价值）：

```
… [蓝牙] 未开启, 第 1/45 次等待(1s 后重试) state=10(OFF) enable()=true
   [蓝牙诊断] state=10(OFF) isEnabled=false 系统路径(BluetoothManager)isEnabled=false
              同一对象=false bluetooth_on=0 addr=02:00:00:00:00:00 已配对=0 enable()返回=true
✔ [蓝牙] 已开启, 继续带外握手
```

**对照车机**：车机 30 次 enable 后 state 一直是 10，真机 1 次就到 11→12。
→ 车机的 Android 蓝牙是**真的起不来**（无硬件 / 固件缺失 / ROM 拦死），不是时序问题。

## 4. 车机上怎么读新日志（1.29 装上后）

1. 开 CarLife → 切到「WLAN 直连」→ 点「下载日志」
2. 找这几行：

```
… [蓝牙] 未开启, 第 1/45 次等待(1s 后重试) state=10(OFF) enable()=true
   [蓝牙诊断] state=10(OFF) isEnabled=false ... bluetooth_on=? addr=? 已配对=? enable()返回=?
… [蓝牙] 尝试改写 Settings.Global(bluetooth_on)=1 → 写入成功 / 无 WRITE_SECURE_SETTINGS 权限
✖ [蓝牙] 已等待 45s 仍未开启(state=10), 放弃蓝牙通道
════════════════════════════════════════
✖ [直连不可用] 车机 Android 蓝牙没能开启 → 直连(WLAN直连)必需蓝牙把 SSID/PSK 送给手机
   ① 车机【设置 → 蓝牙】打开蓝牙并与手机完成配对，再开 CarLife
   ② 改点【热点】页签：车机 WLAN 先连上手机热点
════════════════════════════════════════
```

### 怎么读

| 诊断行 | 结论 | 下一步 |
|---|---|---|
| `adapter=null` | 无 Android 蓝牙硬件 | 直连无解，只能热点/USB |
| `state=10 enable()返回=true` 且 45s 不变 | ROM/固件起不来（**本车机是这个**） | 热点/USB；或刷带 BT 的 ROM |
| `state=10 enable()返回=false` | ROM 拒绝（缺权限 / 用户限制 / 多用户） | 把 App 装成 `/system/priv-app` 再试 |
| `state=11/12` 一直不变 | 卡在开启中 | 等；换固件 |
| `已配对=0` | 蓝牙开了但没配对手机 | 车机设置里先配对 |
| `bluetooth_on=0` 但 App 写不进去 | 全局开关被锁 | 需要系统权限 |

## 5. 副作用 / 风险

- 等待窗口 30s→45s：蓝牙正常时**完全无感**（第一条就 return），只在"开不起来"时多等 15s。
- `sDead` 只在本次进程内有效，重开 App 会重新等一轮（用户中途开蓝牙就来得及）。
- `Settings.Global` 读写全部包在 try/catch 里，无权限只多一行日志，不影响主流程。
- 未改 `d/a.smali` 的任何一行 → 1.20 修的插桩 VerifyError、1.18 的 1s 重试回归项全绿。
