# 1.40 — 亿连式「无蓝牙直连」兜底

> 版本：`_w140` / `patch_v28_无蓝牙直连.py` / versionCode **140** / versionName `mod1.40`
> 成品：`05_产物/CarLife4.0车机端个人修改版1.40_无蓝牙直连亿连式.apk`
> （2,622,713 B，签名 v1+v2+v3，sha256 `3140802708b2a49627067c243b5e853b807133bbc6c58ff7278f2500f97701b3`）
> 需求来源：用户提出「直连必须开蓝牙才行，能不能像亿连(EasyConnect)一样完全不用蓝牙？」

---

## 0. 一句话结论

**蓝牙判死后不再死等热点兜底：自动改走「亿连式」路径——车机直连组本来就是
WPA2 热点，把组名/密码显示在屏幕上让手机在 WLAN 里手动连上，
之后走热点模式 100% 验证过的 UDP 7999 广播发现 → 7 条 TCP → 会话，全程无蓝牙。**

蓝牙正常的设备（如 realme）完全不受影响：兜底只在 BtGuard **判死之后**才触发。

---

## 1. 原理（为什么这样就能绕开蓝牙）

| 原版直连 | 1.40 无蓝牙兜底 |
|---|---|
| 车机 createGroup 建 GO 组 | 相同（组已实测建成功 `DIRECT-cH-CarLife-HU / GO 192.168.49.1`） |
| SSID/PSK 靠蓝牙 SPP 送给手机 | **把 SSID/PSK 打到屏幕日志区**，用户手机 WLAN 手动连接 |
| 手机拿到凭据后 join 组 | 手机像连普通热点一样 join（GO 就是个 WPA2-PSK AP） |
| 手机经 BT 通知 wireless IP | **手机 CarLife 在 UDP 7999 广播**（热点模式实测 100% 的发现链路） |
| 车机 e/b.d(手机IP) 起 7 条 TCP | 相同（复用热点传输 `m/m/e/a` 的原路） |

关键洞察：`m/m/e/a`（热点传输）的 UDP 7999 监听体不关心底层是 SoftAP 还是
P2P GO——只要有 IP 可达的 WiFi 网络就行。蓝牙在直连里的唯一作用就是送凭据，
而这可以用人肉输入替代。

## 2. 实现

### ① `NoBtFallback.java`（新增，logxfer_src）

- `onBtDead()`（幂等）：由 BtGuard 两个判死点调用（无适配器 / 等待 45s 超时）。
  起守护线程做两件事。
- `armTransport()`：反射拿引擎（`a.a.a.a.m.b.a` 静态字段）→ 传输管理器
  （`a.a.a.a.m.d.E`）→ 传输列表（`a.a.a.a.m.m.b.c`），new 一个热点传输
  `a.a.a.a.m.m.e.a` 挂进列表并调 `a()` 启动 UDP 7999 监听。之后手机广播一到，
  `m/m/b.b(本传输)` 的既有机制自动：terminate 其它传输（含蓝牙传输）、
  `e/b.d(手机IP)` 建 7 条 TCP、`q(5)` 起会话。
- `showCredentials()`：自建 WifiP2pManager channel（`getSystemService`，注意
  `getInstance()` 不是公开 API），`requestGroupInfo` 轮询 45×2s；
  本机是 GO → 打印组名 + `getPassphrase()` 真实口令；非 GO → 提示直接开 App。
- 反射目标全部 public 字段（`a`/`E`/`c` 均已确认 public），全程 try/catch 兜底，
  兜底失败绝不崩 App。

### ② `e/d.smali` — keepP2pGroup 闸门（唯一的手工 smali 改动）

`m/m/b.b(传输)` 在「某传输连上」时会 `f()` 掉列表里**其它**传输；直连传输
`e/d.f()` 的 patchE 段有无条件的 `cancelConnect/removeGroup/stopPeerDiscovery`。
不加闸门的话：兜底一连上 → `f(e/d)` → `removeGroup` → 手机刚加入的组被拆 → 会话当场死。

改法（同 1.28 `j.d()V` 抽方法消除共享标签的手法）：

```smali
    invoke-static {}, Lcom/baidu/carlifevehicle/logxfer/NoBtFallback;->keepP2pGroup()Z
    move-result v9
    if-nez v9, :cond_nobt_keep
    invoke-direct {p0, v3, v0}, La/a/a/a/m/m/e/d;->p2pCleanup(WifiP2pManager;Channel;)V
    :cond_nobt_keep
```

三连清理本体收进新增私有方法 `p2pCleanup`。闸门段寄存器分析：v9 两路都是 int、
v7 两路都是 Runnable（都未在段内重赋值）、v3/v0 都是引用 → 合并点无类型冲突。

组残留 BUSY 的自愈：自举器慢扫 removeGroup（1.14+）+ patchK（1.11+）已兜底。

### ③ `BtGuard.java` — 判死文案更新

判死时不再说「直连不可用请改热点」，改为「已自动启用无蓝牙直连，见下方指引」，
并调用 `NoBtFallback.onBtDead()`。

## 3. 用户操作（车机无蓝牙场景）

1. 打开 App 选「WLAN 直连」页签（不用管蓝牙）。
2. 等 45s 蓝牙判死 → 屏幕日志区出现：
   - `✔ [无蓝牙直连] UDP 7999 监听已挂载…`
   - `【无蓝牙直连】① 手机【设置 → WLAN】连接网络: DIRECT-cH-CarLife-HU`
   - `     密码: xxxxxxxx`
   - `  ② 连接后打开手机百度 CarLife → 自动连上车机`
3. 手机照做即可。

## 5. 已知边界（上车前必读）

1. **手机能否连 `DIRECT-` 开头的 WiFi**：P2P GO 的 AP 会出现在大多数手机的
   WLAN 扫描列表里、可当普通热点连。但个别机型会隐藏/拒绝 `DIRECT-` SSID。
   连不上时退回热点/USB 模式即可，不影响其它功能。
2. **首次入组要输一次密码**：4.4 的 `createGroup` 口令是随机生成的（API 16 没有
   setPassphrase），只能显示出来让人输；同网络记住后重连免输。
3. **兜底会话期间组不被强拆**（闸门）：若之后手动切模式，残留组由自举器慢扫清理，
   可能出现一次 BUSY 退避（1.28 三分已处理）。
4. **极小概率双通道竞争**：蓝牙连上的同时手机恰好广播 UDP —— 两个传输几乎同时
   `b()`。先到者建会话、后到者被 terminate；理论上有极小概率双重建链，未观察到。
5. 判死前仍要等 45s（保留 1.29 的 poke 尝试）；车机日志里蓝牙判死固定在 ~45s。
