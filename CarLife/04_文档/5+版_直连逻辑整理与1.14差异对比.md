## 二、新版直连完整流程（整理）

### 阶段 0：UI 前置自检 `m7/f0.a()`

```
蓝牙权限(BLUETOOTH_CONNECT) → 邻近设备权限(NEARBY_WIFI_DEVICES)
  → ACCESS_FINE_LOCATION → WiFi 是否开启 → WifiP2pManager.initialize()
```

任一步失败给中文提示：「蓝牙相关权限未开启」「邻近设备权限未开启」「WiFi未开启」「WLAN直连初始化失败」「当前设备不支持WLAN直连」。

### 阶段 1：蓝牙带外握手 `BluetoothDeviceDiscover`

```
startDiscover() → 注册广播 + post(discoverRunnable)
discoverDevice():
  ├─ adapter 为 null 或未开启 → 只打日志直接 return   ← 不引导开蓝牙
  ├─ targetName = CONFIG_TARGET_BLUETOOTH_NAME
  │    非空 → 遍历 getBondedDevices()，精确 equals 匹配名字
  │    为空 → 反射 isConnected() 过滤，逐个尝试
  └─ createRfcommSocketToServiceRecord(00001101-0000-1000-8000-00805F9B34FB) → connect()
       失败 → Handler.postDelayed(2000ms / 5000ms) 重投（固定周期，无退避、无上限）
```

**注意：新版没有"扫描"环节。** 整个 `instant/` 目录里 `startDiscovery` / `createBond` / `cancelDiscovery` / `BOND_STATE` / `ACL_CONNECTED` / `FOUND` **零命中**，只在 `getBondedDevices()` 里找——完全依赖手机先配对好。

### 阶段 2：P2P 发现 `WifiDirectDiscoverableTask`

```java
// 构造时组装序列
sequence.add(new StopPeerDiscoverOperation(mgr, channel));   // 先停
sequence.add(new DiscoverPeersOperation(mgr, channel));      // 再发现

discoverable() → sequence.execute()
  ├─ executing.getAndSet(true) 已为 true → 直接 return（防重入）
  ├─ op[0] stopPeerDiscovery → onFailure 也转 onSuccess 继续
  └─ op[1] discoverPeers
onFailure(reason) → TimerUtils.schedule(mDiscoverPeers, 2000, 2000)   // 固定 2 秒周期
onSuccess()       → TimerUtils.stop(mDiscoverPeers)
terminate()       → stopDiscoverable() + cancelConnect()
```

### 阶段 3：组形成与 IP 交换 `WifiDirectManager` / `InstantConnectionSetup`

```
WifiDirectManager.onReceive:
  STATE_CHANGED            → p2p 不可用 → isConnected = false
  CONNECTION_STATE_CHANGE  → WifiP2pInfo.groupFormed
                             true  → isConnected=true + callbacks.onDeviceConnected(info)
                             false → isConnected=false
                                     且 getConnectionType()==9 → discoverableTask.discoverable() 重启发现
onDeviceConnected(info) → requestIp(communicator)
  → 蓝牙发 CarLifeMessage(0x108006) 向手机要 IP
handleResponseIp:
  手机回 CarlifeWirlessIp
  ├─ IP 非空 → callback.onDeviceConnected(ip) → WirlessConnector.startConnect(ip)
  └─ IP 为空 且 wifiDirectManager.isConnected() → postDelayed 重发 requestIp  ← IP 就绪轮询
```

### 阶段 4：TCP 连接与保活

```
WirlessConnector.startConnect(ip) → 按 channel 取端口 → TCP 客户端连过去
端口表: 1→7240  2→8240  3→9240  4→9241  5→9242  6→9340  7→9440
成功 → onConnectionAttached() → "WifiDirect onConnectionAttached"

ConnectionEstablishHandler 心跳（★新版独有）:
  启动: TimerUtils.schedule(heartBeatTask, 10ms, 1000ms)
  判定: now - lastReceiveMessageTime > CONNECT_HEARTBEAT_TIMEOUT(默认30s) → terminate()
  未超时: 主动发心跳包 MSG_VIDEO_HEARTBEAT(0x20002)
```

## 三、逐项差异对比

### 3.1 新版有、我们没有的（可移植 ★）

| # | 机制 | 新版实现 | 我们 1.14 | 4.4 可移植性 |
|---|---|---|---|---|
| 1 | **应用层心跳** | 1s 发 `0x20002`，30s 无收包 → `terminate()`；阈值存 SP `CONNECT_HEARTBEAT_TIMEOUT` | **完全没有**（待办 #1，最大短板） | ✅ 纯 Java，可移植 |
| 2 | **P2P 操作串行队列** | `WifiP2pOperationSequence`：`[stop → discover]` + `AtomicBoolean` 防重入 + stop 失败降级为成功 | ✅ **1.6 原生已有**（非缺失）：`a.a.a.a.n.i.b` 序列 + `n.i.c.b`=stop / `n.i.c.a`=discover，`b$a` 的 onFailure 同样降级为成功继续下一操作 | 形态不同、功能等价，**不需移植** |
| 3 | **IP 就绪轮询** | 手机回空 IP 且已连组 → `postDelayed` 重发 `requestIp` | ✅ **1.6 原生已有**（非缺失）：`m.m.d.e :cond_6`，空 IP 且已连组 → `postDelayed` 1s(`0x3e8`) 重发 `requestIp` | **不需移植** |
| 4 | **设备名反向适配** | `DeviceInfoListener` 读系统 `deviceName` → 回填 `CONFIG_WIFI_DIRECT_NAME`（因 API29+ 不能 setDeviceName） | 正向 `setDeviceName` 写系统（patchC，仅 API<29） | ⚠️ `DeviceInfoListener` 是 API 29+；4.4 改用 **`WIFI_P2P_THIS_DEVICE_CHANGED_ACTION` 广播**（API 14+）读 `EXTRA_WIFI_P2P_DEVICE` |
| 5 | **失败分级（用户可见）** | `m7/e0`：reason=1「当前设备不支持WLAN直连」、reason=2「系统繁忙，请稍后再试」 | `j$a` 分级只在 `CarLifeP2PBoot` 日志里，界面无提示 | ✅ 可选 |
| 6 | **前置自检** | `m7/f0`：蓝牙权限/邻近设备权限/WiFi 开关/P2P 初始化，逐项中文提示 | 无 | ✅ 部分可移植（NEARBY_WIFI_DEVICES 是 API 33，4.4 不存在） |

### 3.2 我们有、新版没有的（我们更强 ✓）

| 机制 | 说明 |
|---|---|
| **createGroup 自举器** | 新版**全仓 0 处 `createGroup`**，车机完全被动等手机建组。我们 `j` 类能在手机不建组时自救（但也可能引起 GO 角色冲突，需实测） |
| **setDeviceName** | 新版没有（API29+ 禁止）；我们在 4.4 上可用 |
| **组播锁** | 新版 0 处 `MulticastLock`；我们 `e/e.smali` 有 |
| **DNS-SD** | 新版 0 处 `addLocalService`；我们有（但此前已判断对实际连接可能无用） |
| **蓝牙未开自动 enable()** | **新版蓝牙没开直接 return 不重试**，我们 patchB 会自动 `enable()` —— 这点我们明显更强 |
| **terminate 清理彻底度** | 新版只 `stopDiscoverable + cancelConnect`；我们 `j.b()` 是 `removeGroup + clearLocalServices + release 组播锁 + 停定时器` |
| **USB 免授权** | 1.12 的四层降级；新版走 AOA accessory，是另一条路 |

### 3.3 参数差异

| 参数 | 新版 | 我们 1.14 |
|---|---|---|
| 发现失败重试周期 | **2000ms 固定** | 原版 1000ms；自举器递增退避 6/8/10/12/14s |
| 蓝牙重投周期 | 2000ms（有目标名）/ 5000ms（无目标名），固定、无上限 | patchB enable + 循环 |
| 蓝牙名匹配 | **精确 equals** | 待确认 |
| 蓝牙扫描 | **无**（只查已配对设备） | 有 `startDiscovery` |
| 慢扫上限 | 无上限（2s 无限重试） | 12 轮 × 30s ≈ 7 分钟后放弃 |
| 定时器实现 | `java.util.Timer` + 静态 `LinkedHashMap`（schedule 前先 stop 防重复；但 Timer 单线程，task 抛异常会干掉整个 Timer 线程） | `a.a.a.a.n.h` 调度器 |
| terminate | stopDiscoverable + **cancelConnect** | removeGroup + ... |

### 3.4 完全相同（协议层未变，说明两版手机端协议兼容）

- 蓝牙 SPP UUID `00001101-0000-1000-8000-00805F9B34FB`
- 读同一批配置：`CONFIG_TARGET_BLUETOOTH_NAME`、`CONFIG_HU_BT_NAME/MAC`、`CONFIG_WIFI_DIRECT_NAME`、`CONFIG_WIRLESS_FREQUENCY`、`CONFIG_WIRLESS_TYPE`
- 端口表一致：`7240 / 8240 / 9240 / 9241 / 9242`（新版多出 9340/9440）
- 车机都是 **TCP 客户端**（`startConnect(ip)`），IP 靠蓝牙带外
- 连接类型枚举：2 = USB AOA、5 = 车机热点、**9 = WLAN 直连**
- 传输层 TAG 都叫 `InstantProtocolTransport`
- 失败 reason 语义一致：**1 = P2P 不支持、2 = BUSY**

## 四、结论与建议

**一句话**：两版在**协议层完全同源**（同样的 SPP 带外、同样的端口表、车机同为 TCP 客户端），差异全在**工程化加固**上。新版把"防重入 + 串行化 + 心跳保活"做扎实了，我们把"被动建组自救 + 彻底清理 + 蓝牙自动开"做扎实了——**是互补，不是谁替代谁**。

### 建议移植到 1.15（按收益排序）— 执行结果

1. **心跳探活** ✅ **已移植**（1.15 `m.m.e.f`）：2s 发 `0x20002`、30s(`0x7530`) 无收包 → `f()` terminate。**注意判定门槛**：仅当"本次启动后收到过对端包"（`f.c==1`）才进入超时判定，避免连接建立前误杀。
2. **stop-before-discover 串行队列** ⛔ **不需移植**：1.6 原生已有且 stop 失败同样降级为成功。
3. **IP 就绪轮询** ⛔ **不需移植**：1.6 原生已有（`e.smali :cond_6` + 1s）。
4. **设备名反向适配** ✅ **已移植**（1.15 `d.m`）：用 API14 的 `WIFI_P2P_THIS_DEVICE_CHANGED_ACTION` 读系统 `deviceName` 作兜底（5+ 的 `DeviceInfoListener` 是 API29+，4.4 上没有）。
5. 失败分级的界面提示（可选）— ❌ **未移植**（仍在待办）。

详见 `1.15_vs_5+_对齐度核对.md`。

### 需要警惕的

- 新版的 `TimerUtils` 用裸 `java.util.Timer`：**单线程串行**，一个 task 抛未捕获异常会干掉整个 Timer 线程，后续定时任务静默停止。移植心跳时**不要照抄它的 Timer**，用我们自己的 `a.a.a.a.n.h` 调度器更安全。
- 新版 `BluetoothDeviceDiscover.isConnected()` 反射失败时**返回 true**，会把所有已配对设备误判为"已连接"。别抄。
